# /dividends — 배당락일 타임라인

보유 전 종목의 배당·분배금 일정을 "언제, 얼마를, 확정인지 추정인지"로 정리한다.
갱신은 분기 1회면 충분하다 — 배당 선언이 분기 주기이기 때문이다.

## 절대 규칙

- 조회 전용. 주문 관련 API 사용·작성 금지.
- 확정/추정 구분 의무: 회사·운용사가 선언한 것만 "확정". 데이터 업체가 표시한
  미래 날짜는 회사 발표를 확인하지 못하면 전부 "추정"으로 표기하고 근거
  (과거 패턴)를 1줄 남긴다.
- 매수·매도 권고 금지. "배당락일 전날까지 보유해야 수령" 같은 사실 설명만 한다.
- 모든 항목 출처 URL + 정보등급(A/B/C). 금액은 2출처 교차검증 (fact-researcher 내장).

## 절차

### 1. 보유 종목 로드

```
.venv/bin/python scripts/portfolio_snapshot.py
```

보유 종목·수량이 유일한 기준. 수령 예상액 = 주당 금액 × 현재 보유수량.

### 2. 조사 — fact-researcher 2개 병렬 (동일 메시지에 동시 호출)

- A [개별주]: 배당 지급 여부(무배당도 명시적 사실로 보고), 최근 확정 배당의
  주당 금액·배당락일·지급일·주기, 다음 배당락일(확정/예상 구분).
  ADR은 원주와의 배당락·지급일 차이를 표기.
- B [레버리지·펀드형 ETF]: 분배 주기, 최근 2~3회 지급 이력, 다음 ex-date,
  분배 성격(소득/자본이득/ROC). 운용사 공식 페이지(A급)를 우선.

### 3. 타임라인 정리

- 배당락일 오름차순. 최근 1개월 내 지난 것도 포함 (지급일이 미래일 수 있음).
- 추정 날짜도 정렬을 위해 ISO 날짜로 근사하고 비고에 "9월 중순 예상" 식으로 쓴다.

### 4. 저장 — md + json (대시보드 계약)

- 전문: `reports/dividends-{YYYY-MM-DD}.md` (git 제외 폴더 — 보유 수량 포함)
- 같은 날짜의 `.json`을 반드시 함께 저장 — 대시보드 배당 탭이 최신 파일을 읽는다.
  스키마 고정:

```json
{"as_of": "YYYY-MM-DD",
 "events": [{"ex_date": "YYYY-MM-DD", "ticker": "", "per_share": "", "qty": 0,
             "est_total": "", "pay_date": "", "status": "확정|추정", "note": ""}],
 "no_dividend": ["티커"]}
```

- 대화에는 타임라인 표 + 눈앞의 이벤트(다음 30일) 요약만.

## 비용·시점

fact-researcher 2개 — /research(3개)보다 가볍다. 분기 1회 또는 실적 시즌 직후 실행 권장.
