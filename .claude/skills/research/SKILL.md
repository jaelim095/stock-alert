# /research — 신규 종목 심층 리서치

아직 보유하지 않은(또는 신규 진입을 고민하는) 종목에 대해 두 질문에 답한다:
"살 만한 대상인가" + "내 포트폴리오에 맞는가". 그리고 사기 전에
"언제 팔지(무효화 조건)"부터 정해두게 하는 것이 이 스킬의 존재 이유다.

역할 구분: /checkup = 이미 보유한 것의 점검, /earnings = 실적 이벤트 점검,
/research = 사기 전 조사. 이미 보유 중인 종목이 지정되면 그 사실을 알리고
/checkup을 권한 뒤, 사용자가 원할 때만 계속한다 (추가 매수 검토 용도).

## 절대 규칙

- 조회 전용. 주문 관련 API 사용·작성 금지.
- 타이밍·목표가 예측 금지: "지금이 저점", "$X까지 간다" 류 문장 금지.
  판정은 대상의 질과 포트폴리오 적합성만 다룬다.
- 결론 강제: `후보 적합 / 조건부 관찰 / 부적합 / 판단 보류(정보 부족)` 중 하나.
  양시론 금지, 가장 강한 반대 논거 1개 의무.
- 사실·의견 구분. 확인 못 한 수치는 "미확인" 표기.
- 정보 등급 표기 의무: A(공시·실적 원문·회사 IR), B(주요 언론·데이터 제공업체),
  C(블로그·커뮤니티·추정). 판정 근거로는 A·B만 사용, C는 참고로만 표기.
- 핵심 수치(매출·이익·밸류에이션)는 독립 출처 2개로 교차검증.
  불일치하면 단일값 대신 범위로 표기 (예: "trailing PER 33~38, 출처별 상이").
- 자동 매수 없음. 투자논리 탭 등록도 사용자가 명시적으로 요청할 때만.

## 절차

### 0. 대상 분류 — 유형에 따라 분석 경로가 달라진다

| 유형 | 예 | 경로 |
|---|---|---|
| 개별 상장기업 | NVDA, COST | 표준 경로 (1~7 전체) |
| 지수 레버리지 ETF | TQQQ, SOXL | ETF 구조 경로: 기초지수 구성·배율·감쇠·총보수·추적오차. 기업 렌즈 대신 "구조 이해 + 용도 적합성(단기 트레이딩 vs 장기)" 평가. 레버리지 감쇠 경고 의무 |
| 개별기업 2x ETF | TSLL류 | 기초기업을 표준 경로로 분석 + ETF 구조 리스크(감쇠·변동성 2배) 별도 표기 |
| 비상장·펀드형 | SPCX류 | 기초자산 분석 + NAV 대비 프리미엄/디스카운트 확인 의무. 프리미엄 수치를 못 찾으면 그 자체를 최상위 리스크로 명시 |

- 지수 ETF에 대해 "10년 확실성" 같은 기업 질문을 던지지 않는다. 구조가 본질이다.
- 티커가 모호하면(동명 티커·상장폐지 등) 진행 전에 사용자에게 확인한다.

### 1. 계좌 맥락 로드

```
.venv/bin/python scripts/portfolio_snapshot.py --trades 10
```

- 이미 보유 중인지 확인 (보유 중이면 위 역할 구분 규칙 적용)
- 현재 실질 노출 구성(레버리지 ETF는 기초자산으로 합산)을 4단계용으로 확보

### 2. 사실 수집 — 병렬 리서치 에이전트 3개

동일 메시지에 동시 호출. 각 에이전트는 ToolSearch로 WebSearch/WebFetch를 로드해
조사하고, 판정 없이 사실만 반환한다. 모든 항목에 출처 URL + A/B/C 등급.

- 에이전트 A [사업·경쟁]: 무엇으로 돈을 버는가(부문별 매출 비중), 고객과 시장
  규모, 주요 경쟁사와 점유율(수치·출처), 최근 1년 전략 변화, 해자로 주장되는
  것과 그 증거
- 에이전트 B [재무·밸류에이션]: 최근 2개 분기 실적(매출·이익·마진·가이던스,
  컨센서스 대비), 부채·FCF·희석 여부, 현재 밸류에이션(PER/PSR 등)과
  자사 역사 평균·동종 그룹 대비 위치 — 핵심 수치는 2개 출처 교차검증
- 에이전트 C [리스크·논쟁]: 시장이 보는 최대 리스크 2~3개, 규제·소송,
  약세론자의 논거(공매도 리포트·매도 의견 포함), 최근 3개월 주요 뉴스 2~3개

ETF 경로일 때는 A=구조(지수 구성·배율·리밸런싱), B=비용·추적(보수·괴리·감쇠
실측), C=리스크(변동성·상폐 사례·유동성)로 대체한다.

### 3. 4렌즈 평가 (checkup 체크리스트 재사용)

`.claude/skills/checkup/SKILL.md` 5절의 상세 체크리스트를 그대로 적용한다 —
사업 본질(단영평 관점) / 해자·안전마진(버핏 관점) / 역방향(멍거 관점) /
장기 확실성(리루 관점), 항목별 "증거 없음" 표기 규칙 포함.
신규 종목이므로 특히: "내 능력범위" 항목(이 사업의 성패 요인을 사용자가 스스로
설명할 수 있는가)을 판정에 명시적으로 반영한다.

### 4. 포트폴리오 적합성 — 이 스킬의 고유 단계

- 편입 시뮬레이션: 사용자가 예정 금액을 말했으면 그 금액, 없으면 포트 3%를
  가정해 편입 후 방향별 실질 노출 변화를 계산 (UNDERLYING_MAP 기준으로 동일
  기초자산 합산). 특정 방향 40% 초과가 생기면 경고
- 중복·상관: 기존 보유와 같은 기초자산·지수·테마인지 명시
  (예: TQQQ는 나스닥100 3x — 기존 TSLA·META·PLTR 노출과 높은 상관)
- 레버리지 총량: 편입 후 레버리지 상품 합계 비중
- 봇 연계 제안: 매수하게 되면 감시 방식 제안 — 고변동·트레이딩 성격이면
  LOT(±10% 알림, 설정 탭 등록), 장기 보유 성격이면 대시보드 MA 열람만
  (제안만 하고 실행은 사용자 확인 후)

### 5. 판정 (결론 강제)

출력 형식:

```
### TQQQ — 판정: 조건부 관찰 (확신도: 중간)
- 근거 1 / 근거 2 / 근거 3 (각 1줄, A·B급 출처 기반)
- 가장 강한 반대 논거: …
- 오늘 이 가격에 사겠는가: 예/아니오 + 1줄
- 포트 적합성: (4단계 요약 1~2줄 — 노출 변화·중복·레버리지)
```

- 확신도 기준은 checkup 6절과 동일 (렌즈 충돌 시 낮음, "증거 없음" 3개 이상이면
  판단 보류 고려)
- "조건부 관찰"을 쓸 때는 관찰 조건을 반드시 명시한다
  (예: "다음 분기 마진 개선 확인 전까지 관찰")

### 6. 투자논리 초안 — 사기 전에 파는 조건부터

판정이 무엇이든 작성한다. 부적합 판정이어도 "그래도 산다면 이 조건"을 명시해
두는 것이 가치 있다.

- 매수 이유: 1줄 (이 종목이어야 하는 이유)
- 핵심 가정: 1~2개 (이 투자가 성립하려면 사실이어야 하는 것)
- 무효화 조건: 관찰 가능하고, 가격이 아닌 사업 기준이고, 사용자가 실제로 따를
  문장 (checkup의 좋은 무효화 조건 3요소 준용)
- 초안임을 명시하고, 매수 확정 시 사용자 언어로 다듬으라고 안내한다

### 7. 저장·등록

- 전문을 `reports/research-{TICKER}-{YYYY-MM-DD}.md`로 저장 (git 제외 폴더)
- 대화에는 요약만: 판정 블록 + 포트 적합성 + 투자논리 초안
- 사용자가 매수를 확정하고 등록을 요청하면 투자논리 탭에 추가:

```
.venv/bin/python -c "
from src import config
from src.sheet_client import SheetClient
sc = SheetClient(config.GOOGLE_SERVICE_ACCOUNT_JSON, config.SHEET_ID)
sc.append_thesis([{'ticker': 'TQQQ', 'reason': '…', 'assumption': '…',
                   'invalidation': '…', 'created_at': 'YYYY-MM-DD', 'last_checked': 'YYYY-MM-DD'}])"
```

- 매수 전 선등록을 원하면 가능하되 reason 앞에 "[미보유 후보] "를 붙인다
- 매수가 실제로 일어나면 봇이 체결을 자동 기록하고, 감시를 원하면 설정 탭
  등록(LOT 방식)은 별도로 진행한다

## 비용·사용 시점 안내

실행당 웹 리서치 에이전트 3개 — /checkup(6~8개)보다 가볍다.
신규 진입을 고민할 때, 특히 물타기가 아닌 새 종목에 돈을 넣기 전에 쓰는
도구다. 사용자에게도 그렇게 안내할 것.
