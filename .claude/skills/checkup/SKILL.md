# /checkup — 보유 종목 다관점 점검

ai-berkshire 방법론(4인 관점 분리, 결론 강제, 반대 논거 의무화)을 이 계좌의 실데이터에
적용한다. 목적은 "이 회사를 이 비중으로 계속 들고 있는 게 맞는가"에 답하는 것이다.

## 절대 규칙

- 조회 전용. 주문 관련 API·코드는 어떤 경우에도 사용·작성하지 않는다.
- 타이밍·가격 예측 금지: "언제 사라", "$X까지 간다", "다음 주 반등" 류 문장 금지.
  타이밍은 ±10% 알림 봇의 역할이고, 이 스킬은 종목의 질과 비중만 판단한다.
- 결론 강제: 종목마다 반드시 `계속보유 / 축소 검토 / 추가 검토 / 판단 보류(정보 부족)`
  중 하나. 양시론("한편으론 좋고 한편으론 나쁘다")으로 끝내는 것 금지.
- 모든 판정에 "가장 강한 반대 논거" 1개 필수. 반대 논거가 약하면 판정을 의심할 것.
- 사실과 의견 구분: 리서치에서 확인 안 된 수치는 쓰지 말고 "미확인"으로 표기.

## 절차

### 1. 데이터 수집

```
.venv/bin/python scripts/portfolio_snapshot.py --trades 30
```

보유 종목·평단·손익·비중, 봇 감시 설정, 투자논리(사용자가 기록한 매수 이유·핵심 가정·
무효화 조건), 활성 lot, 최근 매매가 나온다.
이것이 유일한 계좌 사실(source of truth)이다. 기억이나 추정으로 보유 현황을 쓰지 않는다.

### 2. 분석 대상 선정

- 사용자가 종목을 지정했으면(`/checkup TSLA PLTR`) 그 종목만.
- 지정이 없으면: 평가 비중 상위 6개 + 봇 감시 종목 전부 (중복 제거, 최대 8개).
  전 종목 요청 시에만 14개 전부 — 토큰 비용이 크니 기본은 상위 위주.

### 3. 레버리지 ETF → 기초자산 매핑

레버리지 ETF는 펀더멘털이 없다. 기초자산 회사를 분석하고, ETF 고유 리스크를 별도 표기한다.

| ETF | 기초자산 | 분석 대상 |
|---|---|---|
| TSLL | 테슬라 2x | TSLA |
| METU | 메타 2x | META |
| IRE | IREN Ltd 2x | IREN (호주 비트코인 채굴→AI 데이터센터 전환 기업) |

ETF 고유 리스크(항상 명시): 일일 리밸런싱 감쇠(횡보장에서 기초자산보다 나쁨),
변동성 2배, 장기 보유에 구조적으로 불리. 기초자산 판정이 "계속보유"라도
레버리지 ETF 판정은 별도로 내린다 (보유 기간·변동성 감내를 근거로).

### 4. 종목별 리서치 (병렬 fact-researcher)

종목당 fact-researcher 서브에이전트(`.claude/agents/fact-researcher.md`) 1개를
병렬로 띄운다 (동일 메시지에 동시 호출). 수집 태도(판정 금지, 출처·A/B/C 등급,
핵심 수치 2출처 교차검증, 미확인 표기)는 에이전트 정의에 내장되어 있으므로
프롬프트에는 수집 대상만 담는다:

- 최근 분기 실적(매출·이익·가이던스), 최근 3개월 핵심 뉴스 2~3개,
  현재 밸류에이션(PER/PSR), 시장이 보는 최대 리스크 1~2개

### 5. 4인 관점 토론 (메인 세션에서 종합)

각 종목에 대해 네 렌즈로 평가한다. 실존 인물 사칭이 아니라 "~관점"으로 표기.
각 항목은 리서치에서 확인된 사실을 근거로 답하고, 근거가 없으면 "증거 없음"이라고 쓴다.
"증거 없음"이 많을수록 확신도를 낮춘다.

#### 렌즈 1. 사업 본질 (단영평 관점)

- [ ] 뭘로 돈을 버는가 — 5문장 이내 설명. 설명이 안 되면 그 자체가 경고 신호
- [ ] 고객이 왜 떠나지 않는가 — 이 제품이 사라지면 아쉬워할 사람이 누구이고 얼마나 많은가
- [ ] 이익의 질 — 반복 매출(구독·재구매)인가 일회성인가. 매출 성장이 이익 성장으로 이어지는가
- [ ] 본업 집중 — 회사가 본업과 무관한 곳에 돈·경영진 주의를 쓰고 있지 않은가
  (신사업이 본업의 연장인지 문어발인지 구분)
- [ ] 내 능력범위 — 사용자(투자자)가 이 사업의 성패 요인을 스스로 설명할 수 있는 종목인가.
  체크업 리포트를 읽어도 이해가 안 되면 그것 자체를 판정에 반영

#### 렌즈 2. 해자·안전마진 (버핏 관점)

- [ ] 해자 유형 — 브랜드 / 네트워크 효과 / 전환비용 / 원가우위 / 무형자산(인증·라이선스)
  중 무엇인지 특정하고 증거 제시. "기술력이 좋다"는 해자가 아니다
- [ ] 해자 방향 — 넓어지는 중인가 좁아지는 중인가 (점유율 추이·경쟁사 진입 사실로 판단)
- [ ] 가격결정력 — 가격을 올리고도 고객을 지킨 실적 증거가 있는가
  (예: 광고 단가 +12%와 노출 +19% 동시 성장)
- [ ] 수익성의 지속 — 영업마진·ROE 수준이 산업 대비 높고 유지되는가 (수치 확인 시)
- [ ] 자본배분 — 경영진이 번 돈을 주주에게 유리하게 쓰는가
  (자사주·배당 vs 희석·과잉 캐펙스·과도한 보상)
- [ ] 안전마진 — 현재 멀티플이 자사 역사 평균·동종 대비 어디인가.
  성장 가정이 절반만 실현돼도 손실이 크지 않은 가격인가

#### 렌즈 3. 역방향 (멍거 관점) — 가장 강한 반대 논거 담당

- [ ] 부검 질문 — 10년 뒤 이 투자가 실패로 판명됐다고 가정하고,
  부검 보고서의 사망 원인 한 줄을 미리 써본다
- [ ] 단일 실패점 — 한 사람(창업자)·한 고객·한 규제·한 기술에 결과가 좌우되는가
- [ ] 인센티브 왜곡 — 경영진 보상이 주주 이익과 정렬돼 있는가
  (예: 실적 무관 대규모 RSU, 공격적 목표 연동 보상)
- [ ] 보유 편향 점검 — 이 종목을 이미 들고 있어서(또는 손실 중이어서) 유리하게 보고
  있지 않은가. "본전 회복" 논리가 근거에 섞여 있으면 제거
- [ ] 서사 점검 — 판단 근거가 숫자인가 스토리인가. 스토리만 남으면 경고
- 여기서 나온 것 중 가장 반박하기 어려운 것 1개를 "가장 강한 반대 논거"로 채택한다.
  반대 논거가 궁색하면 리서치가 부족한 것이므로 확신도를 올리지 말 것

#### 렌즈 4. 장기 확실성 (리루 관점)

- [ ] 10년 질문 — 10년 뒤 이 회사가 지금보다 클 확률이 높은가 (높음/중간/낮음)
- [ ] 산업 순풍 — 회사가 잘해서가 아니라 산업 자체가 커져서 이기는 구조인가.
  역풍 산업에서 혼자 이기는 그림은 확실성을 낮게 본다
- [ ] 파이 속 몫 — 산업이 커질 때 이 회사 몫이 유지·확대될 구조적 이유가 있는가
- [ ] 생존 체력 — 최악의 거시 환경(고금리·침체)에서 증자 없이 버틸 재무인가
  (순현금/부채, FCF 방향)
- [ ] 확실성과 비중의 정합 — 확실성이 낮은 종목이 큰 비중을 차지하고 있으면
  그 자체를 포트폴리오 진단에서 지적

### 6. 종목별 판정 (결론 강제)

각 종목 출력 형식:

```
### TSLA — 판정: 계속보유 (확신도: 중간)
- 근거 1 / 근거 2 / 근거 3 (각 1줄)
- 가장 강한 반대 논거: …
- 오늘 처음 본다면 이 가격에 사겠는가: 예/아니오 + 1줄
- 투자논리 대조: 유효 / 약화 / 무효화 + 1줄 (기록 없으면 "논리 미기록")
- 보유 맥락: 평단 대비 +64%, 비중 52% (스냅샷 수치 인용)
```

투자논리 대조 규칙: 시트에 기록된 "핵심 가정"이 이번 리서치 사실로 강화됐는지
약화됐는지 판정하고, "무효화 조건"이 실제로 충족됐으면 판정과 무관하게 크게 경고한다.
무효화 조건 충족은 사용자가 스스로 정한 매도 신호이기 때문이다.

확신도 기준 (체크리스트 결과와 연동):

- 높음: 4개 렌즈 전부 긍정 + 안전마진 항목 충족. "오늘 사겠는가"가 예일 때만 가능
- 중간: 렌즈 1개가 부정적이거나, 핵심 변수 1개가 미해소
- 낮음: 렌즈 간 결론이 충돌 — 합리적인 분석자가 반대 판정을 내릴 수 있는 상태
- "증거 없음" 항목이 3개 이상이면 확신도와 무관하게 "판단 보류(정보 부족)" 고려

자동 규칙 (판정과 무관하게 기계적으로 적용):

- 동일 기초자산 실질 노출 40% 초과 → 해당 종목에 "축소 검토" 병기 (임계값은 사용자와 조정 가능)
- 레버리지 ETF 보유 90일 초과 → 감쇠 비용 경고 의무
- 손실 -50% 초과 포지션의 추가 매수(물타기) 논의 시 → 물타기 총액 상한 설정 여부 확인 의무

### 7. 반론 검증 (skeptic)

종목별 판정 초안을 skeptic 서브에이전트(`.claude/agents/skeptic.md`)에 전달해
반박을 받는다. 초안 전부를 한 번의 호출로 묶어 보내 비용을 아낀다.

반박 강도별 처리:

- 치명적: 판정을 재검토한다. 바꾸면 리포트에 "skeptic 반박으로 판정 변경" 명시,
  유지하면 반박을 기각한 이유를 리포트에 남긴다
- 유의미: 판정은 유지하되 "가장 강한 반대 논거"를 skeptic의 반박으로 교체 검토
- 경미/동의: 그대로 진행

### 8. 포트폴리오 차원 진단

- 실질 노출 합산: 같은 기초자산의 ETF를 합쳐서 계산
  (예: TSLA 52% + TSLL 5.5% ≈ 테슬라 방향 58% — 이런 식으로 반드시 합산)
- 레버리지 상품 비중, 섹터 쏠림, 상위 3종목 집중도
- 봇 설정과의 정합: 비중 큰 종목이 감시 밖이면 지적, 추세 종목에 ±10% 임계가
  맞는지 코멘트 (알림 설정 변경은 제안만 하고 실행은 사용자 확인 후)
- 투자논리 미기록 보유 종목 목록 지적 (비중 큰 순)
- 종합 건강도: 우수 / 양호 / 조정 검토 / 위험 중 하나 + 최우선 조치 1개

### 9. 리포트 저장·전달

- 전문을 `reports/checkup-YYYY-MM-DD-HHMM.md`로 저장 (reports/는 git 제외 — 계좌 정보 포함).
  파일명에 시각(HHMM)을 넣어 같은 날 재실행이 이전 리포트를 덮어쓰지 않게 한다.
  종목을 지정한 부분 실행이면 분석한 종목 섹션만 담는다 — 대시보드가 종목별로
  가장 최근 섹션을 병합해 표시하므로 나머지 종목 판정은 유지된다
- 대화에는 요약(종목별 판정 표 + 포트폴리오 진단)만 출력
- 사용자가 이메일 발송을 원하면:
  `.venv/bin/python -c "from src.notifier import Notifier; Notifier()._send_email('[stock-alert] 체크업 요약', open('reports/checkup-….md').read())"`

## 비용 안내

실행당 종목 수만큼 fact-researcher가 돌고 skeptic 호출 1회가 추가된다.
매일 돌리는 도구가 아니라
주 1회 또는 매매 판단 전에 쓰는 도구다. 사용자에게도 그렇게 안내할 것.
