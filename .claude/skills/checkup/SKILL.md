# /checkup — 보유 종목 다관점 점검

ai-berkshire 방법론(4인 관점 분리, 결론 강제, 반대 논거 의무화)을 이 계좌의 실데이터에
적용한다. 목적은 "이 회사를 이 비중으로 계속 들고 있는 게 맞는가"에 답하는 것이다.

## 절대 규칙

- 조회 전용. 주문 관련 API·코드는 어떤 경우에도 사용·작성하지 않는다.
- 타이밍·가격 예측 금지: "언제 사라", "$X까지 간다", "다음 주 반등" 류 문장 금지.
  타이밍은 ±10% 알림 봇의 역할이고, 이 스킬은 종목의 질과 비중만 판단한다.
- 결론 강제: 종목마다 반드시 `계속보유 / 축소 검토 / 추가 검토 / 판단 보류(정보 부족)`
  중 하나. 양시론("한편으론 좋고 한편으론 나쁘다")으로 끝내는 것 금지.
- 모든 판정에 "가장 강한 반대 논거" 1개 필수. 반대 논거가 약하면 판정을 의심할 것.
- 사실과 의견 구분: 리서치에서 확인 안 된 수치는 쓰지 말고 "미확인"으로 표기.

## 절차

### 1. 데이터 수집

```
.venv/bin/python scripts/portfolio_snapshot.py --trades 30
```

보유 종목·평단·손익·비중, 봇 감시 설정, 활성 lot, 최근 매매가 나온다.
이것이 유일한 계좌 사실(source of truth)이다. 기억이나 추정으로 보유 현황을 쓰지 않는다.

### 2. 분석 대상 선정

- 사용자가 종목을 지정했으면(`/checkup TSLA PLTR`) 그 종목만.
- 지정이 없으면: 평가 비중 상위 6개 + 봇 감시 종목 전부 (중복 제거, 최대 8개).
  전 종목 요청 시에만 14개 전부 — 토큰 비용이 크니 기본은 상위 위주.

### 3. 레버리지 ETF → 기초자산 매핑

레버리지 ETF는 펀더멘털이 없다. 기초자산 회사를 분석하고, ETF 고유 리스크를 별도 표기한다.

| ETF | 기초자산 | 분석 대상 |
|---|---|---|
| TSLL | 테슬라 2x | TSLA |
| METU | 메타 2x | META |
| IRE | IREN Ltd 2x | IREN (호주 비트코인 채굴→AI 데이터센터 전환 기업) |

ETF 고유 리스크(항상 명시): 일일 리밸런싱 감쇠(횡보장에서 기초자산보다 나쁨),
변동성 2배, 장기 보유에 구조적으로 불리. 기초자산 판정이 "계속보유"라도
레버리지 ETF 판정은 별도로 내린다 (보유 기간·변동성 감내를 근거로).

### 4. 종목별 리서치 (병렬 에이전트)

종목당 에이전트 1개를 병렬로 띄운다 (Agent tool, 동일 메시지에 동시 호출).
각 에이전트에게 시킬 것:

- WebSearch로 수집: 최근 분기 실적(매출·이익·가이던스), 최근 3개월 핵심 뉴스 2~3개,
  현재 밸류에이션(PER/PSR — 출처 명시), 시장이 보는 최대 리스크 1~2개
- 출처 URL 포함, 확인 못 한 수치는 "미확인" 표기
- 반환: 사실 요약만 (판정은 메인 세션이 내림)

### 5. 4인 관점 토론 (메인 세션에서 종합)

각 종목에 대해 네 렌즈로 평가한다. 실존 인물 사칭이 아니라 "~관점"으로 표기.

- 사업 본질 (단영평 관점): 이 회사가 뭘로 돈을 버는지 5문장 이내로 설명.
  설명이 안 되면 그 자체가 경고 신호.
- 해자·안전마진 (버핏 관점): 경쟁 우위가 구조적인지, 현재 가격이 실수해도
  버틸 여유가 있는 수준인지.
- 역방향 (멍거 관점): 이 투자가 실패한다면 무엇 때문일지. 가장 강한 반대 논거 담당.
- 장기 확실성 (리루 관점): 10년 뒤에도 이 회사가 지금보다 클 확률이 높은가.
  산업 추세가 순풍인가 역풍인가.

### 6. 종목별 판정 (결론 강제)

각 종목 출력 형식:

```
### TSLA — 판정: 계속보유 (확신도: 중간)
- 근거 1 / 근거 2 / 근거 3 (각 1줄)
- 가장 강한 반대 논거: …
- 오늘 처음 본다면 이 가격에 사겠는가: 예/아니오 + 1줄
- 보유 맥락: 평단 대비 +64%, 비중 52% (스냅샷 수치 인용)
```

### 7. 포트폴리오 차원 진단

- 실질 노출 합산: 같은 기초자산의 ETF를 합쳐서 계산
  (예: TSLA 52% + TSLL 5.5% ≈ 테슬라 방향 58% — 이런 식으로 반드시 합산)
- 레버리지 상품 비중, 섹터 쏠림, 상위 3종목 집중도
- 봇 설정과의 정합: 비중 큰 종목이 감시 밖이면 지적, 추세 종목에 ±10% 임계가
  맞는지 코멘트 (알림 설정 변경은 제안만 하고 실행은 사용자 확인 후)
- 종합 건강도: 우수 / 양호 / 조정 검토 / 위험 중 하나 + 최우선 조치 1개

### 8. 리포트 저장·전달

- 전문을 `reports/checkup-YYYY-MM-DD.md`로 저장 (reports/는 git 제외 — 계좌 정보 포함)
- 대화에는 요약(종목별 판정 표 + 포트폴리오 진단)만 출력
- 사용자가 이메일 발송을 원하면:
  `.venv/bin/python -c "from src.notifier import Notifier; Notifier()._send_email('[stock-alert] 체크업 요약', open('reports/checkup-….md').read())"`

## 비용 안내

실행당 종목 수만큼 웹 리서치 에이전트가 돈다. 매일 돌리는 도구가 아니라
주 1회 또는 매매 판단 전에 쓰는 도구다. 사용자에게도 그렇게 안내할 것.
