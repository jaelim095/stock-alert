## 1. 들어가며 — "왜 만들게 되었을까?"

4가지를 목표로 만들었습니다.

1. 대형주, ETF 만으로 돈을 불리긴 쉽지 않다. 레버리지·급등주를 통해 10%만 벌고 나오자. 때가 되면 알림이 와야 한다.
2. 매번 주식 매수/매도 후 메모장에 옮겨 적는 것을 자동화하자.
3. 투자 거장 4인의 의견을 통해 내 주식 평가를 받자 (/checkup, /earnings).
4. 장기 보유하는 대형주는 이동평균선을 통해 보유·추가 매수·매도의 평가를 받자.

1번이 이 시스템의 출발점입니다. 저는 주식을 잘 다룰 줄 모릅니다. 그래서 예적금·ETF·대형주 같은 안전자산 위주로 합니다. 급등주와 레버리지는 절대 장투하면 안 된다고 알고 있고요. 그래서 정한 원칙이 "딱 100만원만 들고 위험주에 들어가서 10%만 벌고 나오자"입니다. 문제는 이 규칙을 지키려면 시세를 계속 봐야 한다는 것. 제가 원한 그림은 이겁니다.

나 : $100에 10주 매수
봇 : "$100 매수내역이 10% 떨어졌습니다. 추가 매수 타이밍입니다" ($90 도달, 카톡)
나 : $90에 5주 매수
봇 : "$90 매수내역이 10% 떨어졌습니다. 추가 매수 타이밍입니다" ($81 도달)
나 : $81에 5주 매수
봇 : "$81 매수내역이 10% 올랐습니다. 매도 타이밍입니다" ($89.1 도달)

매수 건마다 각자의 기준가로 ±10%를 감시하고, 때가 되면 카톡이 오는 것 (→ 3.2절 lot 상태머신). 기록(2번)은 3.1절이, 거장 평가(3번)는 4장이, 이동평균(4번)은 6장 대시보드가 담당합니다.

이 네 가지를 한국투자증권 오픈API와 Claude Code로 묶은 것이 이 시스템입니다.

## 2. 설계 원칙 — 4층 아키텍처

시작 전에 정한 원칙이 세 가지 있습니다.

- 조회 전용 — 주문 API는 코드 자체를 만들지 않는다. 봇이 매매 사고를 낼 방법이 구조적으로 없어야 한다
- 구글시트가 source of truth — 모든 상태는 시트에 있다. 내가 시트를 고치면 봇이 따르고, 랩탑이 날아가도 데이터는 무사하다
- LLM은 판단 보조만 — 알림은 결정론적 코드가, 분석은 LLM이, 결정은 사람이 한다

이 원칙이 4층 구조로 이어집니다.

1층 기계 층 : 파이썬 봇 (LLM 없음) — 체결 기록, ±10% 알림
2층 판단 보조 층 : Claude 스킬 — 거장 관점 분석, 실적 리뷰, 신규 종목 리서치
3층 결정 층 : 사람 — 주문은 항상 내 손으로
4층 표시 층 : Streamlit 대시보드 — 위 층들의 결과를 보여주기만

[이미지 자리 2 : 아키텍처 다이어그램 (draw.io)]

"왜 LLM을 알림 루프에 넣지 않았나"는 자주 받는 질문인데, 답은 간단합니다. 알림은 매일 밤 무인으로 도는 코드라 100% 재현 가능해야 합니다. LLM 분석은 실행마다 결과가 달라질 수 있어서, 사람이 읽고 판단하는 자리에만 둬야 한다고 생각했습니다.

## 3. 기계 층 — 결정론적 봇

### 3.1. Step 1 : 체결 자동 기록 (5분 폴링)

"실시간이 필요한 게 아니라, 빠짐없는 기록이 필요하다."

한국투자증권 오픈API의 해외주식 체결내역 조회를 미국 장중 5분 주기로 폴링해서, 새 체결을 구글시트에 기록합니다. 장외에는 30분 주기로 프리·애프터마켓 체결을 챙깁니다.

"실시간이 아니라 폴링이냐"고 할 수 있는데, 의도적인 선택이었습니다. 한투는 웹소켓 실시간 체결통보도 제공합니다. 하지만 상시 연결 유지·재접속·AES 복호화를 관리하는 비용 대비 얻는 건 "5분 빠른 기록"뿐이었습니다.

웹소켓 (실시간) : 연결 관리 + 재접속 + 복호화 운영 부담
폴링 (5분) : 실패해도 다음 주기에 자연 복구, 멱등 재실행

개인 프로젝트의 운영 부담을 생각하면 폴링이 정답이었습니다. 맥에서는 launchd LaunchAgent로 상시 구동합니다. 미국장은 한국 시간 밤 10시 반부터 새벽까지라, caffeinate -i로 봇이 도는 동안만 맥의 잠자기를 막는 처리도 필요했습니다.

### 3.2. Step 2 : lot 상태머신 알림

"같은 종목이라도 매수 건마다 사연이 다르다."

이 시스템의 알림은 "가격이 X를 넘으면 알림" 같은 밴드 알림이 아닙니다. 매수 건(lot) 단위 상태머신입니다.

- 매수 체결 하나 = 감시점 하나. 같은 종목이라도 5/1 매수분($100)과 5/5 매수분($90)은 각자의 기준가로 독립 감시
- 하락은 계단식 : 기준가 대비 -10%, -20%, -30% 단계마다 한 번씩 알림. 안 사고 버티면 리마인드는 24시간에 한 번만
- 매도가 나가면 어떤 매수 건을 닫은 건지 매칭. 수량이 정확히 일치하는 lot 우선, 없으면 LIFO로 분할 차감
- 매도가 자체도 감시점이 됨. 매도가 대비 -10% 떨어지면 "재매수 타이밍" 알림

알림 채널은 카카오톡 "나에게 보내기"가 메인입니다. 카카오는 refresh token이 60일이라 자동 갱신 로직이 필수고, 갱신이 실패하면 이메일로 경고를 보내고 이메일로 대체 발송하는 fallback 구조를 넣었습니다.

[이미지 자리 3 : 카카오톡 알림 캡처 (금액 마스킹)]

부분 체결 같은 엣지 케이스가 생각보다 까다로웠습니다. 같은 주문이 5주, 5주로 나눠 체결되면 폴링 타이밍에 따라 매칭 결과가 달라질 수 있어서, 주문 누적 수량 기준으로 재매칭하는 로직이 들어갔습니다.

### 3.3. 주문번호 선행 0 폭탄 (트러블슈팅)

구글시트에 주문번호 "0031131042"를 쓰면 숫자로 해석돼 앞의 0이 사라집니다. 그러면 중복 방지 로직이 "0031131042 ≠ 31131042"로 판단해서, 매 주기 같은 체결을 신규로 기록하는 폭탄이 됩니다.

시트 기록 : USER_ENTERED → RAW 모드로 전부 교체
비교 로직 : 선행 0을 정규화해서 비교

비슷한 계열로 상태 저장소의 원자성 문제도 있었습니다. 감시 상태 탭을 clear() 후 update()로 다시 쓰면, 그 사이에 실패했을 때 유일한 상태 저장소가 통째로 비어버립니다. clear 없이 단일 update로 덮어쓰도록 바꿨습니다.

이 두 결함 모두 사람이 아니라 배포 전 다중 에이전트 코드리뷰가 먼저 잡았습니다. 각 발견을 다른 에이전트가 반박 시도하게 해서 오탐을 걸러냈는데, 총 17건의 결함이 이 과정에서 나왔습니다.

### 3.4. 카카오 OAuth 삽질 (트러블슈팅)

카카오 연동은 세 번 넘어졌습니다.

1. 동의항목을 설정하기 전에 로그인해버리면 메시지 권한 없이 앱만 연결됩니다 (403, -402). 연결 해제 후 재인증으로 해결
2. Client Secret을 켜두고 요청에 안 실으면 KOE010. 갱신 요청에도 secret이 필요합니다
3. 인가 코드를 눈으로 옮겨 적다 오타 (KOE320). 결국 localhost:8080에 임시 수신 서버를 띄워 리다이렉트로 코드를 자동으로 받는 방식으로 정리했습니다

## 4. 판단 보조 층 — Claude 스킬 3종

### 4.1. /checkup : 투자 거장 4인의 관점을 코드화

"이 회사를 이 비중으로 계속 들고 있는 게 맞는가."

GitHub에서 화제가 된 ai-berkshire라는 프로젝트가 있습니다 (github.com/xbtlin/ai-berkshire). 버핏·멍거·단영평·리루의 투자 철학을 Claude 프롬프트로 만든 가치투자 프레임워크인데, 이 방법론을 제 계좌 데이터에 연결한 커스텀 스킬이 /checkup입니다.

원본과 다른 점이 셋 있습니다.

1. 데이터 자동 주입 — 원본은 보유 종목을 손으로 입력하지만, 저는 한투 API 잔고와 시트의 매매 이력이 자동으로 들어갑니다
2. 레버리지 ETF 처리 — 2x ETF는 펀더멘털이 없으니 기초자산 기업으로 분석하고(TSLL→테슬라), ETF 고유 리스크(일일 리밸런싱 감쇠)는 별도 표기
3. 타이밍 예측 제거 — 원본은 매수 가격대까지 제시하지만 저는 뺐습니다. "언제 살지"는 1층의 기계적 알림이 담당하고, LLM은 종목의 질과 비중만 답합니다

실행하면 종목별로 리서치 에이전트가 병렬로 돌고, 4개 렌즈(사업 본질 / 해자·안전마진 / 반대 논거 / 10년 확실성)로 평가한 뒤 반드시 하나의 판정을 냅니다: 계속보유 / 축소 검토 / 추가 검토 / 판단 보류. "한편으론 좋고 한편으론 나쁘다" 식 양시론은 프롬프트 레벨에서 금지했고, 모든 판정에 가장 강한 반대 논거 1개를 의무화했습니다.

첫 실행에서 바로 본전을 뽑았습니다. 레버리지 ETF를 기초자산으로 합산하니 테슬라 방향 실질 노출이 포트폴리오의 절반을 넘는다는 게 드러났거든요. 개별 종목으로 보면 안 보이던 집중 리스크였습니다.

### 4.2. 투자논리 시스템 : 감정을 규칙으로

"사기 전에 파는 조건부터 적는다."

시트에 "투자논리" 탭을 만들어 종목마다 세 가지를 기록합니다.

- 매수 이유 : 왜 샀는가
- 핵심 가정 : 이 투자가 성립하려면 뭐가 사실이어야 하는가
- 무효화 조건 : 이게 깨지면 판다

핵심은 무효화 조건입니다. 하락장에서 "지금 불안한가?"가 아니라 "내가 미리 적어둔 조건이 깨졌는가?"를 확인하게 됩니다. 조건이 안 깨졌으면 하락은 (봇이 알려주는) 추가 매수 기회고, 깨졌으면 손실 중이어도 매도 신호입니다. 감정과 규칙이 분리됩니다.

/checkup은 이 탭을 읽어서 매번 "당신이 적어둔 가정이 이번 리서치 사실로 강화됐는지 약화됐는지"를 대조 판정합니다. 백지 평가가 아니라 내 논리에 대한 반증 검사가 되는 거죠.

### 4.3. /earnings · /research : 실적 정독과 신규 종목 리서치

/earnings TSLA라고 치면 발표 원문과 컨퍼런스콜 내용을 수집해서, 컨센서스 대비 평가하고, 투자논리 탭의 핵심 가정에 대해 강화/유지/약화/무효화 중 하나로 판정합니다. 무효화 조건이 실제로 충족되면 리포트 최상단에 크게 경고합니다. 내가 정한 매도 신호를 시스템이 눌러 담지 않게요.

/research는 반대로 아직 사지 않은 종목용입니다. "살 만한 대상인가"와 "내 포트폴리오에 맞는가"를 나눠 평가하고, 편입 시뮬레이션(같은 기초자산 노출 합산)까지 돌린 뒤, 사기 전에 무효화 조건부터 적게 합니다.

## 5. 멀티 에이전트로 확장 — .claude 폴더링

"스킬은 대본, 에이전트는 배우의 계약서."

여기까지 만들고 나니 스킬 3종이 같은 설명을 반복하고 있었습니다. "리서치 에이전트를 띄워라, 판정은 하지 마라, 출처를 달아라…" 이 브리핑이 스킬마다 조금씩 다르게 적혀 있었죠. 최근에 이걸 멀티 에이전트 구조로 정리했습니다.

### 5.1. 에이전트 = 역할이 적힌 임시 직원

에이전트는 신비한 게 아닙니다. 지시문과 도구를 받고 독립적으로 일하다가 결과만 반환하고 사라지는 LLM 실행 단위입니다. /checkup이 돌 때 이미 종목당 1개씩 병렬로 생겼다 사라지고 있었는데, 문제는 그 지시문이 스킬 문서 안에 인라인으로 흩어져 있었다는 겁니다.

AS-IS : 스킬마다 리서처 규칙을 구두 브리핑 (중복, 전달 손실)
TO-BE : .claude/agents/에 역할 정의 파일, 스킬은 이름으로 호출

폴더 구조는 이렇게 정리됐습니다.

.claude/
  settings.json — 기계적 규칙 (권한 allowlist + hooks 등록)
  hooks/check-secrets.sh — 커밋 전 비밀 검사
  agents/fact-researcher.md — 역할 : 사실 수집가
  agents/skeptic.md — 역할 : 반론자

배치 원칙은 층위입니다. 절차(무엇을 어떤 순서로)는 skills/, 역할(누가 어떤 태도로)은 agents/, 어기면 안 되는 규칙은 settings.json + hooks/. 스킬이 대본이라면 에이전트는 배우의 계약서고, 훅은 극장의 소방 설비쯤 됩니다.

### 5.2. fact-researcher & skeptic

fact-researcher는 사실 수집 전담입니다. 판정 금지, 모든 항목에 출처 URL과 정보등급(A: 공시·IR / B: 언론·데이터업체 / C: 커뮤니티) 표기, 핵심 수치는 독립 출처 2개로 교차검증 — 이 규칙이 에이전트 정의에 내장돼 있어서, 스킬 3종이 전부 같은 품질의 리서치를 받습니다.

skeptic은 반론 전담입니다. 이게 만들면서 재미있었던 부분인데, 원래 /checkup의 "가장 강한 반대 논거"는 판정을 내린 본인이 셀프로 썼습니다. 자기가 낸 답을 자기가 채점하는 구조라 약했죠. 지금은 판정 초안이 나오면 skeptic이 받아서 무너뜨리기를 시도합니다.

- 근거가 C급 출처에 기대고 있지 않은가
- 사실에서 결론으로 건너뛴 구간이 있는가
- 보유 중이라는 이유로 유리한 사실만 채집되지 않았는가 ("본전 회복" 논리 검출)
- 반박 강도를 치명적/유의미/경미/동의로 등급화

수집 → 판정 → 반박 → 수정. 역할이 다른 작업자들이 서로의 출력을 주고받는 구조가 되면서, 사람들이 말하는 "멀티 에이전트"가 뭔지 몸으로 이해하게 됐습니다.

### 5.3. 말로 한 약속을 코드로 — secret-scan hook

"조회 전용, 비밀 커밋 금지" 같은 안전 규칙은 원래 프로젝트 문서에 적힌 문장, 즉 약속이었습니다. 약속은 어길 수 있죠. 그래서 훅으로 바꿨습니다.

git commit이 실행되기 직전에 셸 스크립트가 끼어들어 스테이징된 변경을 검사합니다. 금지 경로(.env, secrets/, 토큰 캐시)가 섞여 있거나, 추가된 라인에 비밀 패턴(키 할당문, private key 블록, JWT)이 보이면 커밋 자체가 차단됩니다. 프롬프트로 "하지 마"라고 부탁하는 것과, 시스템이 "할 수 없음"으로 막는 것의 차이입니다.

## 6. 표시 층 — 대시보드, 그리고 웹 버튼으로 Claude 실행하기

마지막으로 이 모든 걸 한 화면에서 보는 Streamlit 대시보드입니다. 보유 현황과 실질 노출(레버리지 합산), 종목별 최근 AI 판정·투자논리·알림 이력, 체크업 리포트를 판정 카드 그리드로 보여줍니다. 전 보유 종목의 이동평균(5/20/60/120일) 현황표도 있습니다. 계좌 전체가 표시되는 화면이라 localhost 전용으로 묶었습니다.

## 7. 사례 : 애플 1년 매매 복기

시스템이 갖춰지니 이런 것도 됩니다. API로 1년 치 체결을 뽑아 매매를 복기해봤습니다.

결과가 흥미로웠습니다. 1년간 15번에 나눠 분할 매도한 것 자체는 일관된 전략이었는데, 단 한 번의 예외가 있었습니다. 하락이 길어지던 구간의 저점 부근에서 나온 매도 — 규칙(하락 시 추가 매수)과 정반대 행동이었고, 그 주식은 이후 넉 달간 34% 올랐습니다.

데이터가 아니었으면 기억도 못 했을 겁니다. 4.2절의 투자논리 시스템(무효화 조건을 미리 적어두기)은 사실 이 복기에서 나온 반성문입니다.

## 8. 마무리

이 시스템 전체를 Claude Code와 페어로 만들었습니다. 사전 조사(API 스펙, 라이브러리 비교)는 병렬 리서치 에이전트로, 코드 리뷰는 다중 에이전트로, 투자 방법론은 스킬로, 반복되는 역할은 서브에이전트 정의로 코드화하는 식이었습니다. 혼자였으면 주말 몇 개를 갈아 넣었을 일이 저녁 시간 며칠로 끝났습니다.

결과를 요약하면:

- 매매 기록 : 수기 0건 → 체결 5분 내 자동 기록
- 알림 : 시세 확인 습관 → lot 단위 계단식 카톡 알림
- 리서치 : 감 → 출처 등급 달린 사실 수집 + 반론 검증 거친 판정
- 안전 : 문서의 약속 → 훅이 강제하는 규칙

마지막으로 하나만. 이 시스템은 조회 전용입니다. 주문 API는 끝까지 붙이지 않을 생각입니다. 기계가 감시하고, AI가 조언하고, 결정은 사람이 한다 — 이 경계가 이 프로젝트에서 가장 잘한 설계라고 생각합니다.
